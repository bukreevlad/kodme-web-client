# Kodme — веб-клиент

**Kodme** — мессенджер и социальная платформа: личная переписка и групповые
чаты, каналы и сообщества, звонки и конференции, трансляции, облако,
мини-приложения и боты. Этот репозиторий — исходный код **веб-клиента**
платформы: SPA без UI-фреймворков, весь интерфейс собран на Tailwind CSS v4.

Клиент работает как обычное веб-приложение в браузере и как **PWA**
(устанавливается на домашний экран, офлайн через Service Worker);

## Ссылки

- **Сервер, развёртывание и документация API** — публичный репозиторий
  дистрибутива: <https://github.com/bukreevlad/kodme>
  (сценарий «git clone → setup.sh → compose up»; документация API —
  [`docs/api/`](https://github.com/bukreevlad/kodme/tree/main/docs/api)).

Исходники этого репозитория публикуются из основного репозитория
платформы скриптом публикации — источник истины там, здесь
фиксируется релиз.

## Требования

- [Bun](https://bun.sh) — сборка, бандлинг и тесты.

## Сборка

```bash
bun install        # зависимости
bun run build      # сборка → dist/ (обычная)
bun run build:secure # сборка с обфускацией main.js
```

Результат (`dist/`) — статика, которую раздаёт nginx веб-сервера
платформы. Файл `index.html` перезаписывается сборкой — вручную его
править не нужно (и нельзя).

Сборке не нужен доступ к серверу: клиент обращается к API и WebSocket
того же origin, с которого раздан (`window.location`), — то есть
работает с любым развёрнутым сервером платформы.

## Релизы

Каждая публикация исходников в этот репозиторий сопровождается вопросом
о версии — она записывается в `package.json` и коммитится. После пуша
GitHub Actions (`.github/workflows/release.yml`) выполняет обычную
сборку и публикует **GitHub Release** с тегом `vX.Y.Z`, ассет —
zip-архив папки `dist` (готовая статика: можно развернуть без установки
Bun — например, положить в `nginx/html/web-client` по инструкции из
[репозитория дистрибутива](https://github.com/bukreevlad/kodme)).

Если релиз с такой версией уже существует — ассет не перезаписывается;
используйте новую версию.

## Проверки

```bash
bun run typecheck  # tsc --noEmit (+ tsconfig для service worker)
bun run lint       # eslint
bun test           # тесты (bun test --watch — в режиме наблюдения)
```

Все три команды должны проходить до коммита.

## Структура

```
js/
  main.ts          точка входа
  sw.ts            service worker (шаблон, заполняется при сборке)
  bot-app-sdk.ts   SDK для мини-приложений ботов (window.WebApp)
  forms/           экраны приложения (формы): <form>/{index.ts, handlers,
                   requests, functions, events, dialogs, components}
  components/      переиспользуемые компоненты (аватары, кнопки, оверлеи…)
  utils/           утилиты (сеть, жесты, медиа, темы, локали…)
  config/          конфигурация (сокет, константы)
  core/managers/   менеджеры уровня приложения
  router/          маршрутизация deep-link'ов
css/               стили (точка входа Tailwind — main.css)
locales/           локализация (ru.json → t())
img/, fonts/       статические ресурсы
tests/             тесты
bun.build.js       сборка (бандлинг, хеши, манифест SW)
```

## Особенности

- **Строгий TypeScript** — флаги `strict` и др. не ослабляются, `any`
  запрещён.
- **Две темы оформления** (светлая/тёмная) — только токены темы
  через `var(--…)`, без жёстких цветов.
- **Мобильный сценарий** — тач-жесты, safe-area, адаптивная вёрстка:
  учитывается при любом изменении кода.
- **Локализация** — тексты только через `t()` из `js/utils/i18n` (ключи в `locales/*.json`), в код не вшиваются; полнота пары ru/en и запрет вшитых строк — тесты `bun test`.
