# Форма поиска (`js/forms/search`)

Модальная форма с вкладками: каналы, сообщества, люди, боты. Открывается из
шапки главной формы, а также используется как вложенная форма выбора
(например, «Назначить модератора»).

---

## 1. Устройство

```
index.js                       каркас формы: жизненный цикл и _template
config/sections.js             ← ЕДИНСТВЕННЫЙ источник правды по категориям
requests/index.js              запрос страницы категории
functions/
  first_loaded.js              первая параллельная загрузка всех вкладок
  load_section.js              догрузка соседней страницы (пагинация по курсору)
  set_section_state.js         «Загрузка…» / EmptyState вкладки / «Ошибка»
  teardown.js                  единая точка выхода
  template_markup.js           разметка вкладок и панелей по конфигу
handlers/
  search.js                    поиск по всем разрешённым вкладкам
  search_section.js            применение ответа одной категории
  on_scroll.js                 догрузка при скролле (троттлинг, проверка краёв)
  on_text_keydown.js           Enter запускает поиск
  create_bot.js                кнопка «Создать бота»
events/store/
  index.js                     подписки сторов на item::added / item::removed
  subscribe_section.js         подписка стора одной категории
components/
  channel.js groups.js users.js bots.js   строки результата (самостоятельные)
```

19 файлов, ~2560 строк. До рефакторинга было 33 файла и 2209 строк: почти всё —
24 копипастных файла, которые отличались двумя-тремя строками.

## 2. Категории: конфиг как единственный источник правды

Всё, что различается между категориями, лежит в `config/sections.js`:

```js
bots: {
    id: "bots",                                  // = ключ объекта (обязательно)
    event: "[search]: get bots",                 // событие сокета
    emptyIcon: "robot",                          // иконка пустого состояния (Tabler)
    createBotKey: "create_bot"                   // кнопка в шапке панели (опционально)
}
```

Состояние пагинации в конфиг не входит: ключи `<id>FirstLoaded`,
`<id>LoadingPrev/Next`, `<id>HasMorePrev/Next`, `<id>ScrollManager`
выводятся из `id` (см. `functions/load_section.js`).

Общий код (`first_loaded`, `load_section`, `on_scroll`, `search`,
`subscribe_section`, `teardown`, `template_markup`) идёт по конфигу и **не знает
имён категорий**.

### Как добавить категорию

1. Запись в `config/sections.js` (событие, `emptyIcon`, опционально кнопка).
   Стор, список, панель, скроллбар и менеджер якоря формы живут под ключом
   `id` (`stores[id]`, `lists[id]`, `panes[id]`, `scrollInstances[id]`) —
   отдельных `storeKey` / `listKey` / `paneKey` в конфиге больше нет.
   Инварианты проверяются тестами.
2. Класс строки: `components/<id>.js` — самостоятельный компонент по образцу
   соседних строк (шаблон, селекторы, подпись, клик).
3. Класс строки в `ITEM_CLASSES` в `events/store/index.js`.
4. Ключи подписи вкладки, подписей строки и пустого состояния в
   `locales/ru.json` (`forms.search.<id>`, `forms.search._components.<localeGroup>`
   и `forms.search.empty.<id>.{title,desc}` — заглушка вкладки при пустом
   поиске; без перевода падает на `forms.search.states.not_found`).
5. Обработчик события `[search]: get <id>` на сервере.

Больше нигде править не нужно. Раньше та же правка требовала синхронно менять
пять-шесть файлов, и «забыть один» означало тихую поломку — например, общий
флаг `isGroupsLoading` сразу у трёх вкладок.

## 3. Сторы и пагинация

У каждой категории **свой** `Store` — это изолирует данные между вкладками
(иначе поиск по людям стёр бы каналы).

| Что | Откуда |
|---|---|
| Курсор «вперёд» | `store.maxId` |
| Курсор «назад» | `store.minId` |
| Продолжение в сторону | `has_more` ответа → `<id>HasMorePrev/Next` |
| Размер страницы | `SEARCH_PAGE_SIZE` (35) |
| Таймаут | `SEARCH_REQUEST_TIMEOUT` (5000 мс) |
| Троттлинг скролла | `SEARCH_SCROLL_THROTTLE_MS` (150 мс) |
| Порог края списка | `SEARCH_LOAD_AHEAD` (15 px) |

Догрузка по скроллу (`handlers/on_scroll.js`):

- проверка не чаще раза в `SEARCH_SCROLL_THROTTLE_MS`, с досылающим вызовом
  (чтобы догрузка не терялась в конце прокрутки);
- измеряются **только два элемента** — первый и последний, плюс `viewport` один
  раз (полный обход `children` давал N принудительных перерасчётов раскладки на
  каждое событие);
- guard `FirstLoaded`: до применения первой страницы direction-запрос не уходит
  (курсора и `has_more` ещё нет);
- у каждой категории **свои** флаги `<id>LoadingPrev` / `<id>LoadingNext`,
  поэтому скролл людей не блокирует догрузку групп, а prev — next;
- `has_more=false` направления закрыто до следующего «Поиск»: тик скролла не
  стучится к серверу в пустоту;
- флаг снимается в `finally`, иначе после первой ошибки вкладка перестала бы
  догружаться до перезагрузки страницы;
- якорь `ScrollManager` (`saveAnchor` → пачка → `update` + `restoreAnchor`):
  prev-пачка препендится в начало, не сдвигая видимую часть панели.

Запрос идёт по **применённой** строке `form.search`, а не по «живому» значению
поля ввода. Иначе можно изменить текст, не нажав «Поиск», и догрузка поехала бы
по новой строке со старым курсором — список становился смешанным. Ответ после
запроса сверяется с применённой строкой: поздняя страница старого поиска в
список нового не встаёт.

## 4. Поиск

`handlers/search.js` ищет **по всем разрешённым вкладкам**, а не только по
активной. Категории запрашиваются параллельно и делят **один номер поиска**
(`form.searchSeq`):

- неудача на одной вкладке не отменяет остальные;
- новый клик по «Поиск» отменяет все ответы предыдущего разом.

> Раньше счётчик увеличивал сам `search_section`, и четыре параллельные
> категории гасили друг друга: к моменту ответа счётчик уже был на 4, поэтому
> применялся только последний ответ, а три вкладки молча оставались со старыми
> данными. Регрессия закрыта тестом.

Стор очищается **после** успешного ответа. Раньше `removeAll()` шёл до запроса,
и упавший поиск оставлял вкладку пустой навсегда.

Enter запускает поиск (`handlers/on_text_keydown.js`). Live-поиска с debounce
нет намеренно: каждая буква — это 4 запроса к серверу, что легко упирается в
`RATE_LIMIT_EXCEEDED`. IME-композиция (`isComposing`) отсекается: при русской
раскладке `keydown` с `Enter` приходит от дедлайна (буква «ё»).

## 5. Жизненный цикл

```
constructor
  ├─ синглтон: три случая (другой контейнер / поиск с параметрами →
  │            закрыть и пересобрать; тот же контейнер с callback →
  │            обновить callback и поднять форму; иначе — вернуть тот же)
  ├─ флаги догрузки, сторы, isClosed, search, searchSeq, ведра отписок
  └─ _init
      ├─ StoreEvents.init  → form.storeUnsubs
      └─ _open
          ├─ _template()
          ├─ new Form(...)
          └─ modal.open()
              ├─ _onBeforeOpen   Tabs, панели по конфигу, скроллбары,
              │                  стартовая вкладка, FirstLoaded() БЕЗ await
              └─ _onOpen         _handlers(): кнопки, Enter, подписки скролла
```

`Form.open()` вызывает `onBeforeOpen` **до** вставки в DOM, поэтому первая
загрузка намеренно не `await`-ится: пользователь видит форму сразу, данные
подставляются через события `item::added`. Ждать сети — значит показать пустой
экран 4 × RTT.

Поздние ответы закрытой формы отбрасываются по `form.isClosed`, иначе
неблокирующая загрузка воскрешала бы DOM после `remove()`.

### Teardown

`functions/teardown.js` — единая точка выхода, порядок важен:

1. `isClosed = true`;
2. отписки сторов (`StoreEvents.destroy`);
3. отписки скролла и полей ввода + отмена таймеров троттлинга;
4. `destroy()` инстансов `OverlayScrollbars`;
5. `removeAll()` на сторах.

Инстанс скроллбара лежит в `form.scrollInstances[id]`.

## 6. Строки результата

`components/<id>.js` — четыре самостоятельных компонента (как строки в других
формах): каждый держит свой шаблон, селекторы, подпись и обработчик клика.
Общей базы нет — различия читаются прямо в файле.

Общий контракт всех четырёх:

- конструктор возвращает **DOM-элемент**, а не экземпляр:
  `list.appendChild(new UserItem(form, data))`;
- копия элемента регистрируется в `data.__domElements__` — по ней
  `item::removed` находит все отображённые копии записи (одна запись может
  попасть в список дважды при гонке одинаковых страниц);
- элементу проставляется `data-id` — по нему `ScrollManager` находит якорь
  скролла, когда prev-пачка вставляется в начало списка (см. раздел 3);
- `update(data)` защищён guard'ом `if (!data) return`.

> Атрибуты имени и подписи в `_setup` обязаны совпадать с шаблоном: опечатка
> не бросает исключение, а молча «теряет» текст — строка выходит без
> названия. Такое уже случалось — названия пропали во всех четырёх списках.
> Сейчас это закрыто тестом, который отдаёт `null` для атрибута, которого
> в шаблоне нет.

Если форме передан `callback`, клик по строкам людей и ботов вызывает его
вместо открытия профиля — это сценарий «выбрать пользователя» для
`group-moderators-manager`.

## 7. Ошибки

Все пользовательские действия показывают тост через `ToastError` с кодами
ошибок сервера (секция get_* запросов поиска):
`INVALID_CURSOR_ID`, `INVALID_DIRECTION`, `INVALID_OFFSET`, `INVALID_USER_ID`,
`USER_ID_REQUIRED`, плюс `RATE_LIMIT_EXCEEDED` по `error.status === 429`.

Тексты — только через `locales/ru.json` (`window._lc.forms.search.*`).

Исключения: **фоновая** догрузка по скроллу. Пользователь ничего не нажимал,
поэтому тост на каждый тик прокрутки был бы шумом — ошибка догрузки
показывается не чаще раза в 10 секунд на категорию
(`SECTION_ERROR_TOAST_REPEAT_MS` в `functions/load_section.js`).

`return false` без контейнеров, флаги догрузки (включая регрессию с общим

IME, отписки и teardown, конфиг категорий, разметка по конфигу, строки

Тяжёлые зависимости подменяются `mock.module`: сокет, тосты, аватар, формы-цели
клика, `OverlayScrollbars`, `Tabs`, `Form`, `DOMParser`. Заглушка `DOMParser`
разбирает HTML шаблона строки на список `data-*` атрибутов и отдаёт узел по
селектору только если атрибут действительно есть в разметке.

## 10. Известный долг

- **N+1 на страницу** на сервере: 35 последовательных запросов меты
  (канал, пользователь, бот). Это существующая архитектура поиска
  на сервере, переписывать её не решились.
- **Асимметрия поиска**: `get_channels` ищет только по `c.name`, `get_users` —
  по имени и по ссылкам, `get_groups` — по ссылкам не ищет.
