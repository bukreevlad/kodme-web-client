# Форма профиля канала (`js/forms/channel-profile`)

Документ описывает устройство формы: вкладки медиа, потоки данных, пагинацию,
жизненный цикл и правила добавления новой вкладки.

---

## 1. Структура

```
js/forms/channel-profile/
  index.js                    # Каркас формы (жизненный цикл + состояние)
  config/media_sections.js    # ЕДИНСТВЕННЫЙ источник правды о вкладках
  handlers/                   # Действия по событиям: настройки, скролл секций
  functions/                  # Пагинация, сборка вкладок, скроллбары, teardown
  requests/                   # Запросы через сокет; карта, собранная из конфига
  components/                 # Классы строк вкладок (photo, video, file, audio, ...)
    handlers/                 # Действия внутри строки (контекстное меню)
  events/store/               # Подписки на события Store (включая Main.store)
```

Правило скелета формы: в `index.js` живут только `constructor`, `_init`, `_open`,
`_template`, `_onBeforeOpen`, `_onOpen`, `_handlers`, `update`, `_onBeforeClose`.
Всё остальное — в подпапках.

## 2. Вкладки — конфиг, а не копипаста

Шесть вкладок медиа описываются **одним массивом** `MEDIA_SECTIONS`
(`config/media_sections.js`). Запись вкладки:

| Поле | Назначение |
|---|---|
| `id` | Идентификатор вкладки, совпадает с `data-target` |
| `storeKey` | Свойство формы со `Store` секции |
| `listKey` | Свойство формы с контейнером списка (DOM) |
| `scrollKey` | Свойство формы с экземпляром `OverlayScrollbars` панели |
| `flagKey` | Свойство формы с флагом «идёт догрузка» |
| `event` | Событие сокета, например `"[channel-profile]: get photos"` |
| `localeKey` | Ключ заголовка вкладки в локали (`forms.channel_profile.*`) |
| `layout` | `"grid"` (фото/видео, три в ряд) или `"list"` (вертикальный список) |
| `icon` | Иконка пустого состояния секции (tabler, kebab-case) |
| `component` | Класс строки секции |

Состояние пагинации секции (см. `functions/load_section.js`) в конфиг не
входит: ключи `<id>FirstLoaded`, `<id>LoadingFirst/Prev/Next`,
`<id>HasMorePrev/Next`, `<id>CursorMin/Max`, `<id>ErrorToastAt`,
`<id>ScrollManager`, `<id>Empty` выводятся из `section.id`.

**Как добавить вкладку:** дописать одну запись в массив. Больше ничего
править не нужно — карта запросов, пагинация, подписки Store, скроллбар,
обработчик скролла и teardown строятся из этого массива автоматически.

Замечание: у вкладки голосовых `id = "audio-notes"`, `localeKey = "voices"`,
`event = get voices` — историческое расхождение, правка `id` сломала бы
deep-ссылки вида `?channel-profile=<id>&tab=...`. Не «чинить» его.

## 3. Состояние формы

| Поле | Назначение |
|---|---|
| `channelId` | Id канала, чей профиль открыт |
| `profile` | Данные шапки профиля (имя, аватар, описание, тип) |
| `tabs` | Экземпляр `Tabs` (вкладки формы), создаётся в `_onBeforeOpen` |
| `photoStore`…`audioNoteStore` | По `Store` на вкладку (объявлены в конструкторе) |
| `listPhotos`…`listAudios` | Контейнеры списков (создаются при сборке вкладок) |
| `<id>FirstLoaded` и др. | Состояние пагинации вкладки — по ключу на каждую секцию, ключи выводятся из `section.id` (см. `functions/load_section.js`) |
| `osInstances` | Реестр экземпляров `OverlayScrollbars` (по одному на панель) |
| `storeUnsubs` | Отписки от событий Store (заполняет `StoreEvents.init`) |
| `handlerUnsubs` | Отписки слушателей скроллбаров (заполняет `_handlers`) |

Store на вкладку — изоляция данных: обновление фото не трогает список файлов.
Стор создаётся в конструкторе, а список — только при сборке вкладок, поэтому
подписки читают список **по ключу в момент события**, а не в замыкании.

## 4. Поток данных вкладки

```
handlers/on_section_scroll.js     # троттлинг 150 мс, проверка только краёв
  └─ functions/load_section.js    # пагинация по курсору CursorMin/Max (крайние
                                  # attachment_id), offset=35, has_more → HasMore*
      └─ requests/index.js        # карта запросов из MEDIA_SECTIONS
          └─ Store.add/update     # → событие item::added
              └─ events/store/subscribe_section.js
                  └─ components/<X>.js  # new → возвращает element
```

- Первая страница грузится при **активации** вкладки (`onActivation` →
  `LoadSection`), а не сразу при открытии: вкладок шесть, открыта одна,
  остальные не грузятся впустую. Гарды (первая загружена, идёт запрос,
  `hasMore* === false`) — внутри `LoadSection`.
- Догрузка по скроллу — только на краях списка: проверяются первый и
  последний элементы, а не все `children` (два `getBoundingClientRect`,
  а не N). Порог — константа `CHANNEL_PROFILE_LOAD_AHEAD`.
- Состояние пагинации живёт на форме по ключам от `section.id`, а не в
  замыкании: иначе каждая вкладка получила бы свой набор независимо от
  конфига, и догрузка слала бы запросы поверх предыдущего.
- `direction: "prev"` **prepended** страницу в начало списка: сервер
  отдаёт старые записи по убыванию id, последовательный prepend складывает
  их в возрастающем порядке. Видимую часть удерживает якорь
  `ScrollManager` (`saveAnchor` → пачка → `update` + `restoreAnchor`).
- Существующая запись **обновляется**, новая — **добавляется**; границы
  курсора `CursorMin`/`CursorMax` пересчитываются по стороне направления.
- Пустое состояние секции показывается только после первой загрузки
  (`functions/update_section_empty.js`), тексты — `forms.channel_profile.empty.*`.

## 5. Жизненный цикл

```
_init            → StoreEvents.init(form)    # 1 подписка Main.store + 6 на секции
_open            → новый Form(...) + modal.open()
_onBeforeOpen    → [channel]: get info (отказ через return false)
                 → Tabs + BuildSections + activateTab + _update
_onOpen          → только _handlers() (подписки скроллбаров)
_onBeforeClose   → Teardown(form) — единая точка выхода
```

`Teardown` (`functions/teardown.js`) вызывается и при обычном закрытии, и из
`catch` у `_open` (там `close()` не вызовется вовсе), и неявно при отказе
открытия: `Form.close()` безусловно вызывает `onBeforeClose` первым делом.

Порядок освобождения обязателен:

1. `StoreEvents.destroy` — отписаться от Store (главный источник утечки:
   `Main.store` живёт вечно и удерживал бы закрытую форму);
2. отписки слушателей скроллбаров (`handlerUnsubs`);
3. `.destroy()` каждого `OverlayScrollbars` из `osInstances`;
4. `removeAll()` на стор секций (подписки уже сняты, событий не будет);
5. удаление инстанса из реестра `ChannelProfile.instances`.

## 6. Ошибки

- `requests/*` только отправляют запрос и **пробрасывают ошибку наружу**.
- Разбор ошибки — в вызывающем коде (`load_section`, `_onBeforeOpen`):
  `ToastError(error, { context, fallback })`, fallback — из локали
  `forms.channel_profile.toasts.*`. Тексты только через `locales/ru.json`.
- Догрузка по скроллу подавляет повторные тосты одной секции не чаще раза
  в 10 секунд (`SECTION_ERROR_TOAST_REPEAT_MS`): скролл — фоновое действие,
  но пользователь должен видеть, что загрузка сломалась.
- Отмена скачивания (`AbortError`) — не ошибка, тоста нет.

## 7. Ссылки и аватары

- Ссылки вкладки «Ссылки» проверяются `utils/links/link_guard.js` (общий с
  messages): внутренние — переход в SPA, внешние — диалог подтверждения.
- Аватар автора сервер не отдаёт для записей медиа (намеренно, см. чеклист
  I2): `Avatars` получает `name` без `id`, чтобы цвет не считался от id
  сообщения. Не «чинить», передав `id` сообщения.

## 8. Контекстное меню строки и переход к сообщению

Каждая строка секции умеет открывать контекстное меню
(`components/handlers/context_menu.ts`): состав пунктов собирается по типу
строки, а не дублируется в каждом компоненте.

| Пункт | Когда показывается |
|---|---|
| `copy` | Ссылки, у которых есть адрес для копирования |
| `download` | Файлы, аудио, голосовые (там, где есть ветка скачивания в локали) |
| `go_to_message` | Есть `id` сообщения-владельца (см. ниже) |

**Источник `id` сообщения** — `functions/get_message_id.ts`
(`getSectionMessageId(data, kind)`):

- вложения (фото/видео/файлы/аудио/голосовые) — `entity_context:
  { type: "message", id }`, который сервер возвращает в записях всех пяти
  секций;
- строка вкладки «Ссылки» — это **само сообщение**, поэтому `kind = "message"`
  и берётся `data.id`.

У записи нет `entity_context` — пункта «Перейти к сообщению» нет.

**Открытие меню.** У строк-сеток (фото/видео/ссылки) вместо нативного
`click` подключён `GestureController`: `tap` открывает медиапросмотр
(фото/видео), долгое нажатие на мобильном и правый клик на десктопе — меню.
Контроллер уничтожается через `destroy()`, который вешается в
`data.__destroy__` и вызывается из `events/store/subscribe_section.ts`.

**Переход** — `functions/go_to_message.ts` (`goToMessage(form, messageId)`):

1. Если чат канала не открыт — создаёт `Messages({ channelId })` и ждёт его
   первой отрисовки (подписка на `item::added` + проверка реестра форм, так
   как группа с темами снимает инстанс до отрисовки; таймаут 10 с).
2. Закрывает профиль — под ним открывается чат.
3. Берёт запись сообщения из стора чата; если её нет — догружает через
   двухшаговый запрос истории с `offset: 1` (курсоры истории исключительные,
   `id > cursor` / `id < cursor`, поэтому само сообщение запросом по своему id
   не достать) и показывает тост `toasts.message_not_found`, если достать
   не удалось.
4. Вызывает общий `goPointMessageHistory` (`messages/functions/`) — он либо
   подсвечивает и прокручивает к сообщению, либо пересобирает окно вокруг
   него запросами истории в обе стороны.
