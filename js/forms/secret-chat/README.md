# Форма секретного чата (`js/forms/secret-chat`)

Документ описывает устройство формы секретного чата (WebRTC P2P): потоки данных,
отправка сообщений и правила, по которым здесь добавляются хендлеры и утилиты.

Форма **намеренно устроена по образцу `js/forms/messages/`** (та же структура
папок, лента с окном сообщений, батчеры, жесты строки). Правило связанной
формы: при изменении поведения в `js/forms/messages/` проверяй, касается ли
это секретного чата, и при необходимости сделай аналогичную правку здесь
(и наоборот).

---

## 1. Структура

```
js/forms/secret-chat/
  index.ts                 # Каркас формы (жизненный цикл + состояние)
  handlers/                # Действия по событиям: клики, ввод, контекстные меню
  functions/               # Логика формы: загрузка истории, лента, шапка, статусы
  components/              # Строка сообщения и футеры ответа/редактирования
    handlers/              # Действия внутри компонента сообщения
    dialogs/               # Вложенные диалоги (подтверждение удаления сообщения)
  dialogs/                 # Диалоги формы (удаление чата)
  events/
    store/                 # Подписки на события Store (рендер строки из Store)
    manager/               # Подписки на события SecretChatsManager (DataChannel)
```

Правило скелета формы: в `index.ts` живут только `constructor`, `_init`, `_open`,
`_template`, `_onBeforeOpen`, `_onOpen`, `_handlers`, `update`, `_onBeforeClose`.
Всё остальное — в подпапках и вызывается из нужной точки жизненного цикла.

## 2. Ключевые отличия от `forms/messages/`

| | `messages` | `secret-chat` |
|---|---|---|
| История | сервер + IndexedDB (кэш) | **только локальная** IndexedDB (`secret_messages`, vault-шифротекст) |
| Доставка | через сервер | **P2P DataChannel** (очередь «не доставлено» живёт в `SecretChatsManager`) |
| Пагинация | keyset по id (`[channel_id+id]`) | keyset по `created_at` (`[chat_id+created_at]`) |
| Текст сообщения | HTML-экранирован сервером (рендер после `unescapeHtml`) | открытый plaintext (хранится в шифротексте); markdown-it с `html:false` экранирует сам |
| Статусы | pending/temp + галочки по `display_last_viewed_message_id` | `queued/sending/sent/delivered/read/failed` из записи (`read` ставит `ReadReceiptsBatcher`) |
| Сущность | канал (группы/каналы/боты) | чат «один-на-один», привязанный к паре устройств |
| Реакции/кнопки/пересылка/системные сообщения | есть | **нет** (не предусмотрены секретными чатами) |

## 3. Состояние формы

| Поле | Назначение |
|---|---|
| `store` | Сообщения в окне чата (`utils/store.ts`, окно 300 элементов) |
| `chat` / `chatId` | Локальная запись `secret_chats` (статус, таймер, верификация) |
| `peerName` / `peerAvatar` | Имя и аватар собеседника (профиль загружается при открытии) |
| `connectionState` | Состояние P2P-соединения (для подзаголовка шапки) |
| `typingStatusText` | «печатает…» / «записывает…» (гаснет по таймеру) |
| `textarea`, `textareaAutosize` | Поле ввода и его авторазмер |
| `readReceiptsBatcher` | Батчер квитанций «прочитано» входящих |
| `typingStatus` | Троттлинг исходящих статусов активности |
| `storeUnsubs` / `managerUnsub` | Отписки от событий Store и менеджера |

Всё, что нужно погасить при закрытии, гасится в `_onBeforeClose()`: отписки,
батчер (с flush), статус активности, observer.

## 4. Поток отправки

```
handlers/create_message.ts
  └─ canSend(...)                       # синхронная проверка ДО отправки
  └─ SecretChatsManager.sendMessage     # запись в secret_messages (status=queued)
       └─ _flushQueue                   # доставка при живом соединении
            └─ событие message::added → events/manager → Store → DOM
```

Очередь «не доставлено», ретрансляция `failed`, ротация ключа при
реконнекте — забота `SecretChatsManager` (`js/core/managers/secret_chats_manager.ts`);
форма только рендерит статусы из записи.

## 5. Прочтение

- `functions/intersection.ts` — единственный источник событий видимости:
  видимое входящее без `status="read"` ставится в `ReadReceiptsBatcher`.
- Батчер шлёт один control-кадр `receipt: read` не чаще раза в 700 мс;
  после успешной отправки локальные записи получают `status="read"` —
  маркер непрочитанных уходит, у собеседника появляются двойные галочки.
- Без соединения квитанции не уходят: ids остаются в батчере и отправятся
  при следующем срабатывании.

## 6. Ошибки API

Ошибки разбираются через `parseError`/`toastError` (`js/utils/ui/toast_error.ts`),
как в `forms/messages/`. Запрещено: `catch` с одним `Logger.error(error)` для
пользовательского действия — пользователь должен увидеть тост.

## 7. Как добавлять хендлер

1. Положите файл в `handlers/` (действие формы) или `components/handlers/`
   (действие внутри сообщения). Сигнатура: `export async function <camel>Handler(form) {...}`.
2. Подключите его в `_handlers()` файла формы / в `_actions` компонента.
3. Тексты тостов — только через `locales/ru.json` (`forms.secret_chat.*`).
4. Логи — через `Logger` с контекстом вида `[app][secret-chat][что-делаем]`.
